# Client V14.2.2

Le client reste un bridge vers le serveur ; depuis 14.2.1 le **jeton est facultatif** :
le service hébergé accepte les requêtes anonymes sous plafonds opérateur, et
l'endpoint public est la valeur par défaut. Il ne contient pas le modèle, les clés
API fournisseur ni le noyau de vérification.

## Nouveautés 14.2.2 (correctifs terrain)

- `check` et `claim → verify` acceptent les **comparaisons** (`62 >= 70`) avec
  `expected: "true"|"false"`, avec le même noyau exact que `calculate`.
- `plan`/`reason` exécutent le **déterministe d'abord** : une décision Jev
  `clarify` ne bloque plus les claims exactes et la clarification est **scopée**
  aux claims sémantiques concernées ; `frontier` expose chaque claim avec
  `category`/`selected`/`reason`.
- `semantic_segment` gagne `granularity: coarse | sentence | atomic` (offsets
  littéraux, confiance, lien parent).
- `run_create` expose `availability` (`semanticInferenceAvailable`,
  `externalResearchAvailable`, raison) et avertit si l'objectif semble nécessiter
  une interprétation alors que l'externe est coupé.
- `budget_status` nomme clairement `baseRunBudget`, `profileMultiplier`,
  `effectiveRunBudget`, `consumed`, `held` (alias `limits`/`budgetLimit` conservés).
- Documentation : [ARCHITECTURE](ARCHITECTURE.md) (flux de données
  `dataClass` × `externalAllowed`), [SECURITY](SECURITY.md), [RELEASE_V14](RELEASE_V14.md).

## Sélection de catalogue

```bash
export SMART_THINKING_TOOL_PROFILE=math
npm start
```

Profils : full (défaut), math, research, code, audit. Par programmation :
`await connection.tools('research')`. Les outils absents du serveur ne sont
jamais inventés. Les erreurs de profil sont explicites. Ce filtre de contexte
n'accorde et ne retire aucune permission : le serveur garde l'autorité.

Math inclut calculs en lot et finis, solveurs, cas et vérification ponctuelle.
Research inclut recherche, fetch, dossiers et lecture d'artefacts nécessaires.
Pour une tâche hybride ou le catalogue complet, garder full. Le profil code
n'est pas une promesse d'exécution arbitraire sur le serveur.

## Reprise

`npm ci --ignore-scripts && npm run check`. Le core doit être déployé et testé
avant publication stable. Une recette inter-dépôts existe dans le core ; elle
utilise le vrai client et un serveur HTTP de test. Seuls les tests de V14.2 sont
prévus pour les nouvelles campagnes, sans relancer de systèmes historiques.

`publishConfig.tag` vaut latest depuis 14.2.1. Aucun npm publish, merge ou déploiement
automatique n'est ajouté. La configuration est optionnelle : endpoint public et accès
sans jeton par défaut ; `SMART_THINKING_MCP_URL` / `SMART_THINKING_MCP_TOKEN_FILE`
restent des surcharges (jeton = quota nominatif supérieur).
Le profil wire reste smart-thinking-mcp/14.0 : les nouvelles affordances sont
additives. Les chiffres historiques de README ne sont pas des résultats V14.2.
