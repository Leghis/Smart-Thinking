**Q2 — Impossibilité du mapping TEAM→v1**

Énumération exhaustive du booléen `shared` (2 valeurs, R07 : pas de 3ᵉ valeur cachée) :
- `shared=false` → accès **{O}** ≠ {O,T} → **perte de T**.
- `shared=true` → accès **{O,T,X}** ≠ {O,T} → **divulgation à X**.

**Aucun des 2 mappings ne préserve {O,T}.** Le produit **ne peut pas** satisfaire simultanément TEAM exact + v1 inchangé + rollback exact **sans modifier une exigence** : il faut soit accepter la fin de support v1 (R06), soit renoncer à l'exactitude TEAM.

**Q3 — Migration par phases et point de non-retour**

P0 état initial → P1 expansion (ajout `visibility`, `shared` conservé) → P2 lecteur v2 bi-format → P3 écritures v2 → P4 backfill concurrent **avec CAS sur version** → P5 validation → **P6 activation TEAM** → P7 contraction (suppression `shared`).

- **Dernier point où un rollback v1 exact reste possible : fin de P5 (validation).**
- **Point de non-retour exact : P6 (activation TEAM)** — dès qu'une ligne TEAM est écrite ou une copie TEAM délivrée, R08 interdit le retour exact (données et copies persistent).

**Q4 — Protocole de promotion (liaison sans tag)**

Approbation = tuple signé `(digest_artefact, digest_suite_H, digest_plan_migration, digest_config, digest_données_cible)`. Le déploiement vérifie l'égalité **octet à octet** de chaque digest ; un tag mobile est rejeté (R02). **Mise à jour du plan après approbation** : toute modification du plan invalide l'approbation → nouvelle approbation requise (le digest du plan entre dans le tuple).
