### Q2 — Condition nécessaire de partage de cache et analyse K-a..K-d

**Condition nécessaire (et suffisante pour la sûreté) :** une clé `K` est sûre pour un ensemble de réponses protégées **ssi**
`K(m₁)=K(m₂) ⟹ Réponse(m₁)=Réponse(m₂)` — c'est-à-dire que `K` **raffine** la partition induite par le contenu effectif (droits effectifs + données). Toute collision de clé entre deux contenus distincts est une fuite potentielle.

**Analyse (énumération exhaustive de 256 mondes = principal × org × dossier × action × finalité × rév. politique × langue × version de représentation) :**

| Clé | Définition | Sûre ? | Contre-exemple |
|---|---|---|---|
| K-a | chemin (+langue) | **Non** | `[LUNE,17,fr]` : v1 vs v2 → contenus différents |
| K-b | org + dossier | **Non** | `[LUNE,17]` : p_lune (autorisé) vs p_soleil (DENIED) |
| K-c | org + dossier + nom de rôle | **Non** | `[LUNE,17,AGENT]` : même rôle nommé, droits différents (R01) |
| K-d | contexte d'autorisation complet + révision données + langue + version | **Oui** | aucune collision de contenu |

**Politique concrète retenue :** pour toute réponse protégée, **ne pas mettre en cache partagé** (CDN) ; si cache nécessaire, clé = `K-d` (principal, org, objet, action, finalité, révision de politique, révision de données, langue, version de représentation) **et** `Cache-Control: private, no-store` + `Vary` explicite. Le CDN actuel (chemin+langue, ignore Cookie/Vary) doit être **exclu** des routes protégées.

**Pourquoi une clé n'est pas un contrôle d'accès :** la clé ne fait que *partitionner* le stockage ; elle ne *décide* rien. Une clé correcte évite les collisions, mais si le point de décision (R02) n'est pas vérifié à la lecture, un cache peut servir une entrée périmée après révocation. La clé est une condition de *cohérence de stockage* ; l'autorisation est une *décision serveur atomique*. Les deux sont nécessaires et non substituables.

### Q4 — Ordre logique et réparation de l'API

**Ordre logique (énumération des 6 permutations de {R révocation, L lecture, M mutation}) :** seuls **L+M+R** et **M+L+R** garantissent que L et M ont leur point de décision **avant** R. Règle : *une lecture/mutation n'aboutit que si son point de décision (évaluation atomique de politique, R02) précède la révocation R*. La révocation est une écriture sérialisée dans le même domaine.

**Réparation de l'API (R06) :**
1. **Organisation dérivée côté serveur** (session), jamais d'un champ JSON client.
2. **Supprimer `allowed=true`** fourni par le frontend : la décision est serveur.
3. **Session serveur + jeton anti-CSRF** (cookies automatiques ⇒ protection requêtes forgées).
4. **Validation atomique de la politique** au point de décision, avec révision de politique.
5. **Idempotence** via `opId` (rejeu sans double effet).

**Mutation dont l'annulation navigateur n'a pas annulé l'effet (P04) :** l'annulation est une tentative de transport sans garantie (R05). Traitement : le serveur renvoie un **accusé portant le contexte d'exécution** (`org=SOLEIL`, `opId`, révision). Le client affiche **séparément** « opération exécutée dans l'ancien contexte SOLEIL » et « état affiché dans le contexte actuel LUNE » (R07). On ne réécrit **jamais** le JSON en transit pour substituer LUNE à SOLEIL (falsification d'identité, réfutée).

### Q5 — Non-divulgation (R08), impossibilité P06, garantie honnête

**Propriété de non-divulgation (périmètre R08) :** *Pour tout dossier d'une organisation O, aucun octet de contenu ni signal d'existence n'est émis vers un contexte dont le point de décision n'autorise pas (principal, O, objet, action, finalité, révision).* Preuves : (a) rendu serveur contrôle **avant** émission (corrige P02) ; (b) caches protégés en `K-d`/`no-store` (corrige P03) ; (c) réponses étiquetées par génération et rejetées si périmées (corrige P01) ; (d) messages d'erreur **indifférenciés** (pas de distinction contenu/existence inter-organisations). **Limite explicite :** la propriété porte sur les *émissions futures* ; elle ne retire pas les octets déjà délivrés (R02).

**Impossibilité P06 (prouvée) :** avec N appareils et un appareil isolé (aucun canal), la suppression immédiate de toute copie partout est impossible. Énumération exhaustive des 2³ = 8 états de connectivité : **7 échouent** (témoin `[0,0,0]`). Aucun canal ne peut contacter un appareil isolé ⇒ « supprimer immédiatement toute copie, tous appareils » est **réfuté**.

**Garantie produit honnête :** « Une révocation bloque **toute nouvelle lecture ou mutation** dont le point de décision est postérieur à la révocation, sur les appareils joignables, dans un délai borné par la prochaine synchronisation. Les copies déjà délivrées ne sont pas retirées ; les appareils hors ligne sont purgés à leur reconnexion. Aucune mise à jour légitime déjà autorisée n'est perdue. »

## Limites / impossibilités

- **Établi :** fuites P02, P03 (divulgation), P04 (mutation indûment autorisée), P01 (affichage erroné) ; insuffisance de K-a/K-b/K-c ; sûreté de K-d ; ordre L+M+R / M+L+R ; impossibilité de P06.
- **Réfuté :** « altérer le JSON en transit SOLEIL→LUNE » (falsification d'identité) ; promesse P06 (suppression immédiate partout).
- **Non déterminé / hors périmètre :** canaux temporels et compromission OS (R08) ; le modèle ne suppose pas un navigateur hostile, mais **toute donnée déjà envoyée peut avoir été copiée** — aucune architecture ne peut la retirer. La non-divulgation garantit les **émissions futures**, pas la rétroactivité. La propagation inter-onglets n'est pas instantanée (R05) : la garantie est bornée par la prochaine synchronisation.
