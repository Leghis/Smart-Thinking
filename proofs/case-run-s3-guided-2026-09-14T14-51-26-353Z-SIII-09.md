## Réponse

### Q1 — Coupes minimales de l'architecture initiale
Dans le modèle de causes {A, B, N, K, V}, une seule cause survient à la fois. Le chemin initial exige : un domaine physique vivant (frontends en A et B), N, K, V, et un quorum 2/3 sur {n1, n2, n3} avec n1, n2 ∈ A et n3 ∈ B.

**Coupes minimales = {A, N, K, V}** (4 coupes) :
- **A** : tue n1 et n2 → il ne reste que n3 → quorum 2/3 perdu (et frontends A perdus).
- **N** : chemin introuvable (R04).
- **K** : accès interdit (R04).
- **V** : toutes les instances de la génération principale incapables de servir (R04).
- **B** n'est **pas** une coupe : n3 tombe mais n1, n2 survivent → quorum conservé.

**Pourquoi 3 réplicas et plusieurs régions ne suffisent pas** : la tolérance « panne unique de réplica » (R02) est un énoncé sur les *réplicas*, pas sur les *domaines*. Deux réplicas sur trois partagent le domaine A : une panne de domaine A est une panne *collective* qui emporte 2/3 du quorum. De plus, N, K et V sont des **racines logiques uniques** hors du quorum : aucun nombre de réplicas ne les supprime (R04 : « un pod de plus ne supprime aucune de ces dépendances »).

### Q2 — Chemin de service complet après correction
Chemin corrigé, chaque élément préinstallé/testé (R06) :
1. **Routage** : point d'entrée alternatif authentifié, sans dépendance à N (F-entrée).
2. **Identité/clés** : clés locales conservées, validation des usagers déjà enregistrés sans appel à K (F-clés).
3. **Révocation** : lue dans le quorum (R06), donc cohérente avec l'autorisation courante.
4. **Quorum** : réplicas répartis dans **trois domaines physiques distincts** — n1→A, n2→C, n3→B (F-placement).
5. **Logiciel** : génération de secours G-safe indépendante de la faute V (F-version).

**Sûreté/disponibilité conditionnelle par panne unique** (énumération exhaustive) :

| Cause | Réplicas vivants | Quorum ≥2 | N,K,V hors chemin | Service |
|---|---|---|---|---|
| A | n2, n3 | oui | oui | OK |
| B | n1, n2 | oui | oui | OK |
| C | n1, n3 | oui | oui | OK |
| D | n1, n2, n3 | oui | oui | OK |
| N | n1, n2, n3 | oui | oui | OK |
| K | n1, n2, n3 | oui | oui | OK |
| V | n1, n2, n3 | oui | oui | OK |

Toute panne unique de R05 laisse ≥2 réplicas joignables et n'atteint aucune racine logique du chemin de secours. Les écritures validées restent durables sur le quorum (R02) ; les clients n'écrivent jamais sur une copie minoritaire.

### Q3 — Nécessité des quatre familles
Modèle de couverture : F-placement couvre {A, B}, F-entrée couvre {N}, F-clés couvre {K}, F-version couvre {V}.

- **F-placement** : sans elle, A (ou B) emporte 2/3 du quorum → coupe. Nécessaire.
- **F-entrée** : sans elle, N rend le chemin introuvable → coupe. Nécessaire.
- **F-clés** : sans elle, K interdit l'accès → coupe. Nécessaire.
- **F-version** : sans elle, V rend la génération principale incapable de servir → coupe. Nécessaire.

L'unique ensemble couvrant minimal est **{F-placement, F-entrée, F-clés, F-version}** : retirer n'importe quelle famille laisse une cause non couverte.

**Ce n'est pas une preuve d'optimalité universelle** : la nécessité est établie *dans cette architecture* (P02 le précise explicitement). Un autre design (par ex. un point d'entrée unique multi-fournisseur, ou un schéma sans état WAITLISTED) pourrait couvrir la même cause par un mécanisme différent. On prouve une nécessité locale, pas un minimum universel de produits.

### Q4 — Traitement de P07
P07 est une **fausse restauration** : G-safe ignore WAITLISTED et le lit comme FREE → le document change de sens (R01 exige une interprétation exacte, pas un simple HTTP 200).

**Engagement de compatibilité requis avant d'activer WAITLISTED** :
- (a) Le **schéma** déclare WAITLISTED et sa sémantique, versionné.
- (b) Le **lecteur de secours** doit soit interpréter WAITLISTED correctement, soit **refuser explicitement (fail-closed)** — jamais le mapper silencieusement à FREE.
- (c) Les **writers** ne doivent pas produire d'état non interprétable par la génération de secours autorisée.
- (d) **Qualification indépendante** de G-safe avant activation (R07 : « faire évoluer et qualifier indépendamment la génération de secours avant de l'autoriser »).

### Q5 — Bilans carbone et choix minimax
Coûts exacts : C(n) = 2·300·n + 50·n + 6000 = **650n + 6000** ; D(n) = 5·100·n + 200·n + 1000 = **700n + 1000**.

| Charge | C | D |
|---|---|---|
| 50 | **38 500** | **36 000** |
| 200 | **136 000** | **141 000** |

**Seuil d'égalité** : 650n + 6000 = 700n + 1000 → 50n = 5000 → **n = 100 travaux**.

**Choix minimax** (pire cas, sans probabilité) :
- pire cas C = max(38 500 ; 136 000) = **136 000**
- pire cas D = max(36 000 ; 141 000) = **141 000**
- **136 000 < 141 000 → choisir C.**

**Pourquoi E et le seul classement par intensité ne répondent pas** :
- **E** est inadmissible pour le stockage personnel (R01/P03) ; le réplica votant contient ces données, et le chiffrement ne change pas la politique de localisation. E est donc hors domaine admissible, quelle que soit son intensité.
- Le **classement par intensité seule** (C : 300 g/kWh > D : 100 g/kWh) désignerait D, mais ignore les termes dominants : consommation (2 vs 5 kWh), transfert (50 vs 200 g) et coût fixe (6000 vs 1000). Le bilan complet inverse le classement pour n=200 et le minimax tranche pour C.

### Q6 — Plan d'injection et garanties non déductibles
**Plan d'injection** (chaque cause *collective*, séparément, jamais un pod unique — cf. P06) :
1. **A** : couper tout le domaine A (n1, n2 + frontends A).
2. **B** : couper tout le domaine B (n3 + frontends B).
3. **N** : couper le DNS/point d'entrée N.
4. **K** : couper le coffre/service central K.
5. **V** : injecter la faute de génération principale.
6. **Reprise de version** : écrire un document WAITLISTED, injecter V, démarrer G-safe, vérifier l'interprétation.

**Vérification métier** (R01) à chaque injection : lecture d'une ressource, réservation, autorisation courante, **durabilité d'une écriture validée**, lecture des révocations dans le quorum, et non-régression de version.

**Garanties chiffrées NON déductibles de ce dossier** :
- Aucun **MTTR/MTBF**, aucun **RTO/RPO** numérique : R05 ne fournit qu'un « délai borné » sans valeur.
- Aucune **probabilité de panne**, donc aucune **disponibilité en %** (l'énoncé l'interdit explicitement).
- Aucune garantie contre compromission cryptographique, deux pannes simultanées, ou panne de tous les capteurs de santé (hors garantie R05).
